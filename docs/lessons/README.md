# 教训归档（docs/lessons/）

> 本目录归档 rschange 重构过程中沉淀的调试教训与面试素材。
> 两份素材的原文件位于旧仓库（只读参考）：`Debug_lesson.txt`、`project2-lessons-and-interview.txt`。
> 本目录下的文件是**整理版**：旧文里的过时路径与版本表述已全部替换为新仓库的真实位置，
> 每条结论均附可复核的落点（`文件:行号` 或 测试名）。

## 文件索引

| 文件 | 一句话说明 |
|---|---|
| `debug-lessons.md` | 旧仓库 13 条调试教训的整理版：逐条给出现象 / 根因 / 修复 / 新仓库落点 / 复发判据，并显式标注哪些条目在新仓库**无守护**；另含「面积口径修正」专题（`1441800` → `720900` m²）。 |
| `interview-notes.md` | 可直接照着讲的项目讲述稿：30 秒版与 2 分钟版介绍、技术亮点（带可核查数字）、难点与取舍、8 组追问应答、以及**诚实边界**（当前仍未做到的事项，避免面试被追问时翻车）。 |

## 使用约定

1. **声明式表述**：`debug-lessons.md` 全篇使用「必须 / 禁止 / 应当 / 需要」句式，不含第一人称叙述。
   `interview-notes.md` 的口语讲述段落是话术稿，允许第一人称，属唯一例外。
2. **数字必须有据**：所有数字取自 `docs/verification/phase-2.md`、`phase-2.1.md`、`phase-3.md`、`phase-6.md`
   或当期仓库事实采集。无法核实的数字一律标 `待核实`，**禁止**在对外讲述中当作既成事实。
3. **缺陷编号有三套口径并存**，引用时必须标明来源文档，见 `debug-lessons.md` §0。
4. **无守护条目不得隐去**：`debug-lessons.md` 中对「新仓库没有对应守护」的条目显式标注 `无守护` 并给出原因；
   补充守护时应同步更新该标注与「如何避免复发」字段。

## 维护触发条件

| 触发事件 | 需更新的位置 |
|---|---|
| 新增一条调试教训 | `debug-lessons.md` §1 总表 + §2 新增小节（字段须与既有条目一致） |
| 某条 `无守护` 条目补上了测试 | 改为具体 `文件:行号`，并移除 `无守护` 标注 |
| 基线数字变化（`7209` / `720900` m² / Otsu `5.9168`） | §3 面积口径专题 + `interview-notes.md` 技术亮点数字 |
| 测试规模变化（pytest / ctest / vitest 计数） | `interview-notes.md` §2 数字表 |
| 容器实际构建、端到端实测完成 | 移除 `interview-notes.md` 诚实边界中对应条目 |
